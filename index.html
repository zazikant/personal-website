How It Works

Three steps from document to answer.

No model training, no fine-tuning, no infrastructure to babysit. Just upload, ask, and read.

01 / INGEST
📄

Upload or paste

POST a PDF (FormData or base64), a markdown file, or raw text to /api/upload or /api/ingest. Files up to 4.5 MB are accepted — the Vercel serverless payload limit. Metadata like doc_type, project, and version is stored alongside every chunk so you can filter later.

POST /api/upload · /api/ingest
02 / INDEX
🧠

Chunk, embed, store

Documents are split into semantic chunks, embedded with NVIDIA embedding models, and upserted into a Pinecone vector index. Each chunk carries its filename, doc_type, project, version, and uploaded_at — so retrieval can be filtered and every answer can be traced back to its exact source document.

NVIDIA embeddings · Pinecone
03 / ANSWER
💬

Retrieve, reduce, cite

Query expansion rewrites synonyms before retrieval. Top-K chunks are pulled from Pinecone, grouped by filename, and reranked by avgScore * log(chunkCount + 1). An LLM reducer synthesizes a single answer with conflict detection and lists every source filename.

POST /api/query · /api/query-stream
What's Inside

Built for trust, not just recall.

Every feature exists to make the answer verifiable — so you can ship it inside real workflows without second-guessing the output.

🔍

Query Expansion

Synonyms are expanded automatically. “Owner” matches “responsible”, “lead”, “manager”. “API” matches “endpoint”, “rest”, “service”. Recall goes up without you rewriting the question.

📚

Document Aggregation

Chunks are grouped by filename and reranked by avgScore * log(chunkCount + 1). Multiple relevant chunks from the same doc merge into one coherent context window.

⚗️

LLM Reducer

A dedicated reducer LLM synthesizes multi-chunk answers, extracts key points, detects conflicting information across sources, and produces a single unified response — not a stitched-together list.

🎯

Two Retrieval Modes

Conversational mode (top-K=12) for broad exploration. Precise mode (top-K=5) for specific facts. Switch per question — same index, different retrieval shape, no re-indexing.

🏷️

Metadata Filters

Filter queries by doc_type, project, or version. Scope a question to a single project, a specific doc type, or a tagged release.

🔁

Add · Replace · Delete

Upload modes handle the full lifecycle. Replace auto-deletes old chunks at the same filename before inserting new ones — no stale duplicates, no manual cleanup, no orphaned vectors.

📎

Source Citation

Every answer includes a sources array of filenames. Only files that still exist in the documents table are returned — deleted docs are never cited.

⚡

Streaming Answers

Use /api/query-stream for token-by-token streaming. Same retrieval, same citations, faster perceived latency for chat-style UIs.

🧹

Index Reset

One call to DELETE /api/index/reset wipes every Pinecone record. Useful for dev cycles, migrations, or starting a second brain from scratch.

API Reference

Talk to the brain directly.

Base URL: https://rag-document-assistant-2.vercel.app

POST /api/query 
# Ask a question — conversational mode (top-K = 12)
curl -X POST "https://rag-document-assistant-2.vercel.app/api/query" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is the architecture?",
    "mode": "conversational"
  }'

# Response
{
  "answer": "The synthesized answer...",
  "sources": ["doc1.md", "doc2.pdf"],
  "aggregatedContext": "Key Points: ...",
  "debug": {
    "hitsFound": 7,
    "documentsAggregated": 3,
    "reducerUsed": true
  }
}
